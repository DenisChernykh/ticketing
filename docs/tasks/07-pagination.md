# 7. Пагинация по курсору

[Все задачи](../../README.md#tasks)

**Задача.** Пользователь открывает следующую страницу заказов, а между запросами появляются новые покупки. Уже показанные записи не должны повторяться.

**Решение.** Передавать в курсоре дату и id последней строки. Следующая страница выбирается относительно этой пары, а не числового смещения. Для каталога дополнительно проверяется ревизия порядка: если состав или порядок мероприятий изменился, API просит начать просмотр заново.

**Код решения:**

- [PgOrderQueries.list()](../../apps/sales/src/modules/orders/infrastructure/pg-order-queries.ts#L18) — выбирает заказы по паре `created_at DESC, id DESC` и формирует `nextCursor`.
- [PgCatalogQueries.page()](../../apps/sales/src/modules/catalog/infrastructure/pg-catalog-queries.ts#L22) — читает страницу мероприятий и проверяет ревизию порядка.
- [decodeCursor()](../../packages/core/src/pagination.ts#L18) — проверяет формат курсора и его принадлежность конкретному списку.

**Проверки:**

- [Новые записи между страницами](../../test/integration/lifecycle.test.cjs#L79) — не сдвигают следующую страницу заказов; чужой курсор отклоняется, устаревший курсор каталога получает `CURSOR_STALE`.
