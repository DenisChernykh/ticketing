# 2. Повтор запроса без второго заказа

[Все задачи](../../README.md#tasks)

**Задача.** Сервер создал заказ, но клиент не получил ответ. Повтор запроса должен вернуть ту же покупку.

**Решение.** Сохранить `Idempotency-Key`, отпечаток параметров и ответ вместе с заказом в PostgreSQL. Одинаковые ключ и параметры возвращают сохранённый ответ, в том числе при одновременных запросах. Другие параметры с тем же ключом получают `409`.

Повтор возвращает первоначальный ответ с бронью `reserved`. Актуальный статус заказа читается через `GET /orders/{id}`.

**Код решения:**

- [CheckoutService.purchase()](../../apps/sales/src/modules/checkout/application/checkout.service.ts#L23) — сравнивает параметры запроса и возвращает сохранённый результат повтора.
- [PgOrders.claimKey()](../../apps/sales/src/modules/orders/infrastructure/pg-orders.ts#L8) — занимает ключ и координирует конкурентные запросы через `ON CONFLICT` и `FOR UPDATE`.
- [PgOrders.completeKey()](../../apps/sales/src/modules/orders/infrastructure/pg-orders.ts#L20) — сохраняет исходный ответ в той же транзакции, что и заказ.

**Проверки:**

- [Параллельные повторы](../../test/integration/product.test.cjs#L117) — восемь запросов возвращают один orderId; второй API возвращает тот же результат; изменение количества даёт `409`.
- [Откат первой попытки](../../test/integration/product.test.cjs#L142) — освобождает ключ и позволяет повторить запрос.
