# Дизайн фронтенда Ticketing

Результат этого этапа — **статический редактируемый макет Pen и техническое решение**.
Это не работающий фронтенд: кнопки, оплата, таблицы и состояния показывают будущие сценарии.
Код приложения и API на этом этапе не изменяются.

- [Редактируемый исходник Pen](ticketing.pen) — все экраны, компоненты и технические примечания.
- [PDF всех 13 экранов](ticketing-screens.pdf) — последовательный просмотр desktop и mobile.

  необходимые будущие дополнения, сессии, асинхронные состояния и критерии приёмки.
- [Каталог учебных задач](../README.md#tasks): задачи бэкенда, которые становятся наблюдаемыми функциями интерфейса.
- [Запуск и демонстрационные сценарии](../README.md): существующий стенд, роли и учебная покупка.

## Состав макета

Восемь основных desktop-экранов шириной 1440 px: каталог, мероприятие, вход,
мои заказы, заказ, мероприятия организатора, редактирование мероприятия и отчёты.
Дополнительно создан вариант формы создания мероприятия.

Четыре мобильных экрана шириной 390 px: каталог, мероприятие, мои заказы и заказ.
В макете также созданы восемь повторно используемых компонентов и состояния брони,
оплаты, выпуска билетов, отмены, возврата, конфликта версий, загрузки и ошибок.

## Проверка

Проверены desktop 1440 px и mobile 390 px, переносы текста, размеры элементов управления,
независимые состояния заказа/платежа/выдачи и соответствие видимых действий API.
Проверка геометрии Pen не обнаружила обрезаний; незавершённых placeholder-фреймов нет.
Дополнительно проведена независимая визуальная проверка создания мероприятия, мобильных заказов,
билетов, ошибок и диалогов. Полный набор билетов показывается даже при сбое уведомления.

Исходник нарисован через MCP и сохранён в `design/ticketing.pen`.
Файл следует открывать и редактировать через Pen; экспортированные PNG и PDF предназначены для просмотра.
